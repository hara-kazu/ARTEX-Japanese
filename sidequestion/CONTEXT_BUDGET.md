# サイド質問の長い対話とコンテキストの予算

2026-09-11 に修正。元の実装では、リクエスト JSON の文字数をそのまま token とみなし、メインタスクの 32K の出力予約を引き継いでいたため、HTML、JS、ツール結果が多い場合、通常のサイド質問を早い段階で拒否していました。

## オープンソース実装の確認

- [Grok CLI のサイド質問のコンテキスト](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739)：最近のユーザーとアシスタントの文章から抜粋し、文字数の予算は約2000、1件当たり最大400文字です。この経路では、継続的なサイド質問と回答の履歴を保持していません。
- [Grok CLI の独立したリクエスト](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts)：独立した取り消しシグナルを使用し、モデルが対応する場合の出力上限は2048 tokensです。ツールは提供しません。
- [Grok CLI のメインセッションの圧縮](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts)：token を推定し、最近の内容を保持し、新しい内容を以前の要約へ反映し、ターンをまたぐ切り詰めも処理します。
- [OpenCode のセッションの圧縮](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts)：リクエスト全体の推定、出力 / バッファーの予約、最近の内容と更新型の要約、ツールなしの要約リクエストを使用します。この実装では、最近の内容の予算の既定値は8000、要約の出力上限は4096 tokensです。
- [OpenCode の上限超過からの復旧](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts)：アシスタントの出力がまだ始まっていない場合だけ、上限超過からの復旧を試みます。復旧後の呼び出しは、同じ復旧経路に再び入りません。

ARTEX は、独立した出力予算、最近の内容と更新型の要約、回数を制限した復旧の方式を参考にしています。norma v0.3.6 の構造化メッセージとツールの対応を保持し、Grok の文章の抜粋方式をそのまま使いません。OpenCode のメインセッションの圧縮イベントを、ARTEX のメイン transcript に書き込みません。

## リクエストの予算と実行

- メッセージには、norma のコンテンツブロックごとの UTF-8 バイト数による推定と4/3の余裕を使用し、システムプロンプト、ツール schema、メッセージの包装の追加コストも含めます。推定は、モデルの正確な token 数ではありません。
- サイド質問の出力は既定で最大8192 tokensで、メイン設定に指定された出力上限も超えません。サービスの環境変数 `ARTEX_BTW_MAX_OUTPUT_TOKENS` で256–32768の上限を設定できます。製品の既定モデルやメインタスクのパラメーターは変更しません。
- 入力予算は、コンテキストウィンドウから出力上限と安全余裕を引いた値です。ウィンドウが不明な場合は、プラットフォームの既定値200Kを使います。安全余裕はウィンドウの5%で、最小128、最大8192 tokensです。
- 成功した質問と回答は、増加する連番順に、1回最大20組ずつ読み込みます。原文を保持するのは最大20組で、その token 予算は入力予算の最大1/4、かつ16K以下です。
- 超過した質問と回答は、更新型の要約に反映します。要約には履歴の出典とコンテキストの時刻を付けます。過去のアシスタントの回答は新しいツールの証拠と同じではなく、矛盾する場合は最新のメインスナップショットを優先します。
- メインコンテキストがまだ長すぎる場合は、コピー内の古いメッセージだけを要約し、最近の内容を最大8K tokens保持します。切り詰めの境界では、ツール呼び出しと結果を分断しません。大きすぎる1組は、全体を要約対象にします。
- 要約の入力は、実際の残りウィンドウに合わせ、UTF-8を壊さず分割します。出力上限は2048 tokensで、空の要約、切り詰め、ツール呼び出し、要約予算の超過はいずれもキャッシュへ書き込みません。1回のサイド質問で要約の呼び出しは最大12回で、同じ120秒のタイムアウトに従います。上限に達したら明示的に失敗し、無限には繰り返しません。
- モデルが最初にコンテキスト超過を返し、まだテキストやツール呼び出しを出力していない場合は、さらに縮小して最大1回再試行します。推定サイズが減らなければ、直ちに復旧を停止します。他のモデルエラーや、部分的にストリーミング出力した場合は、この復旧を行いません。
- 要約、失敗した試行、取り消し時の使用量を含め、取得した使用量はすべて同じサイド質問のリクエストに加算します。Provider が使用量を返さない場合は、引き続きゼロしか記録できず、推定値を実際の使用量として扱ってはいけません。

## 永続化と画面

`side_question_sessions.memory` は、以前の質問と回答の要約、対象の ordinal、スナップショットの識別情報ごとにキャッシュしたメインコンテキストの要約を保存します。`side_question_requests.context_info` は、準備段階、実際に再提示した組数、要約の使用状況、予算の推定を保存します。

要約は、元のリクエストが実行中で、消去バージョンが一致する場合だけ保存します。消去時にはキャッシュも削除し、遅れて到着した書き込みで消去済みのデータを復元しません。新しいスナップショットには、古いスナップショットの要約を再利用しません。要約フィールドは v3 のタスクアーカイブに保存します。復元する古い v3 にフィールドがない場合は空のオブジェクトを補い、v1/v2 にも引き続き対応します。

POST は、まずリクエストを受け付けて返し、準備と圧縮はバックグラウンドで実行します。受け付けのロックやデータベースのトランザクションは保持しません。SSE / 履歴には、準備、質問と回答の整理、コピーの圧縮、回答の段階を表示し、圧縮の失敗はそのサイド質問のリクエストの失敗した最終状態として保存します。フロントエンドはエラーを保持し、今回失敗した質問の下書きを復元します。入力欄を隠す浮動通知は使わず、履歴の定期取得で送信エラーを消さないようにします。
